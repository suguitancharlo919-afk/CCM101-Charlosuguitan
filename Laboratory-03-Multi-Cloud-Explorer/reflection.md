# Laboratory 03 Personal Reflection

Completing this multi-cloud evaluation activity has significantly broadened my understanding of modern infrastructure. Among the three major cloud platforms, Google Cloud Platform impressed me the most. Its structural focus on containerization and developer-friendly design feels incredibly modern, especially since Google natively created Kubernetes. The cleaner interface and intuitive layout make GCP feel much more approachable for a student like me who is still mastering cloud management workflows.

During my research, I realized that despite their different branding strategies, AWS, Azure, and GCP share deep structural similarities. They all operate on the same foundational pillars: compute instances, object storage buckets, isolated virtual networks, and granular identity access controls. Whether a service is called Amazon EC2, Azure Virtual Machines, or Google Compute Engine, the underlying architectural concepts and resource rules remain practically identical.

However, I learned that choosing between these platforms depends entirely on specific business requirements. A cloud solutions architect cannot just pick a platform based on personal bias; instead, architectural choices must align with budget constraints, existing software setups, and growth plans. For example, a company embedded in the Microsoft ecosystem naturally fits Azure, while a global e-commerce giant needs the mature multi-region capacity of AWS. Acting as a Cloud Solutions Consultant taught me that my real job is to translate complex business problems into reliable, cost-efficient cloud designs.

Finally, completing this mission has elevated my GitHub Cloud Computing Portfolio. It has transformed from a simple terminal log into a professional documentation showroom. By adding structured platform comparison tables, cloud service matrices, and my client recommendation challenge, my repository now proves that I can analyze high-level cloud environments and document technical solutions effectively.
